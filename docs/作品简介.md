# 作品简介

> GOAI 赛道一【新智基座｜Agent Infra】· 选题方向四：金融风控与理赔自动化（信贷风控与贷后处置）
> 队伍名称：`Durandal` ｜ 成员：`李家宝` · `刘泽苑`

---

**项目名称**：信衡 CreditSentry — 贷后风险预警到授信处置的多 Agent 可举证自主闭环系统

**问题与场景**：银行不缺贷后预警系统，缺的是预警之后那一段。四个痛点：预警海量、筛查成本高；核查跨工商 / 司法 / 征信 / 流水多系统，证据分散耗时；报告与处置靠人工，标准不一、经验难复用；监管要求可追溯可复核，而证据链不足。其中第三、四条才是门槛——前两条是效率问题，后两条是责任问题，责任问题解决不了，系统只能停在「给人看的建议」。

**核心解决方案**：以 AgentTeams 为协同基点，构建 1 Manager + 1 TeamLeader + 6 Worker 的端到端闭环：信号聚合 → 尽调取证 → 风险定性 ⇄ 对抗质疑 → 分级处置 → 合规审计与经验回流。TeamLeader 以 SOP 五阶段状态机 + 12 条路由规则做编排，**LLM 只做阶段内判定、不决定流程走向**——金融场景要求可复现，而自由编排不可复现即不可审计。能力沉淀为 16 个 Skill（领域判断 12 个全自研，通用云操作复用官方能力并标注开源等价替代），外部系统经 4 个 MCP Server 接入，Mock 与真实接入零 Schema 差异。

**创新点**：①**内控即拓扑**——把《商业银行内部控制指引》的「不相容职务分离」编译为权限矩阵，Agent 数量由权限等价类推导而非拍脑袋（6 = 5 个权限等价类 + 1 个目标函数对立拆分），同一份矩阵同时驱动运行时授权、Worker 配置生成与回归断言；②**证据账本 + 对抗裁决**——无证据不决策，质疑环节不可跳过且覆盖率参与裁决，「未被质疑的主因 ≠ 质疑通过」，对抗双方强制绑定不同模型族以避免自洽坍缩；③**四维执行闸门 L0–L3**——风险等级 × 证据等级 × 敞口金额 × 可逆性，不可逆动作永不自动执行，入参缺失时失败即阻断而非放行，带幂等键与回滚点；④**降级方向恒为阻断**——模型失效判「质疑未完成」阻断、取证不足转人工且必须产出可派发的取证任务清单，系统放弃自动处置时的最后一个动作是把工作交接清楚。

**开放 / 复用价值**：计划开源 Agent 拆分法则（CC BY 4.0）、EvidenceLedger 证据账本、RiskGate 四维闸门、CreditSkill Spec 规范三件套、4 个 MCP 接口契约（均 Apache-2.0），以及含误报陷阱样例的风险案例回放数据集（CC BY 4.0）。可迁移的是骨架与约束——信号归并 → 证据固定 → 对抗式判定 → 按可逆性分级处置 → 留痕审计，可平移至保险核赔、供应链金融、反洗钱调查与工业设备运维；不可迁移的是判定口径，它绑定具体监管条款，换行业必须重写。

**当前进展**：三条端到端链路全部跑通并覆盖三种闸门结局——风险成立（审批后执行）、误报驳回（维持原状）、真实历史回溯（只出方案不执行）。其中回溯链路把时钟冻结在 2017-04-01，只喂入该日之前的公开信息，历史结局在数据构造时即被摘出、全程结构上不可达。已交付 74 项安全边界回归、906 组 Skill 评估、13 个接大模型的故障模式回归，全绿；另有可在浏览器操作的风险处置工作台，审批环节真实阻塞等待人工决策。运行时零第三方依赖、零云账号、零网络。数据全部为合成与公开数据，不含任何真实银行客户数据。

**当前边界**：真实行内系统尚未接入（4 个 Server 仍为 Mock，接口契约已按零差异设计）；9 个 Skill 的评估集仍为种子集，覆盖度差额已如实记录；Nacos 与 Higress 仅在配置层预留；接大模型已在故障注入伪端点上跑通全部 13 个模式与完整链路，但尚未在真实商业端点上跑过。敞口升档阈值目前对所有客户分层使用同一套绝对值，在大型集团客户上会把几乎所有可逆动作推到最高档——机制是对的，标定不对，复赛将改为按客户分层参数化。
