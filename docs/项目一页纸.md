## 目标场景与核心问题

商业银行小微与对公信贷的**贷后管理**，四个真实痛点：

1. 风险预警数量庞大，人工筛查成本高，客户经理难以及时识别真正高风险事件；
2. 风险核查涉及工商、司法、征信、流水等多个系统，证据分散、核查耗时；
3. 贷后报告和风险处置依赖人工撰写，标准不统一，经验难以沉淀复用；
4. 处置全过程需满足监管要求的可追溯、可解释、可复核，现有系统证据链管理不足。

**核心洞察**：瓶颈不在「发现风险」，而在**敢不敢动手**。压降额度、提前收贷会直接影响
企业经营，误判即引发投诉与监管问责。所以我们做的不是 AI 预警，是**可举证的自主处置闭环**。

## 方案概述

以 AgentTeams 为协同基点，1 Manager + 1 Team Leader + 6 职能 Worker 完成端到端闭环：
信号聚合 → 尽调取证 → 风险定性 ⇄ 对抗质疑 → 分级处置 → 合规审计与经验回流。
Team Leader 采用 SOP 五阶段状态机路由，**LLM 只做阶段内判定、不决定流程走向**，
路由决策本身落为 Trace Span，「为什么走了这条分支」可举证、可回放。

## 多 Agent 架构

| Agent | 权限等价类 | 关键约束 |
|---|---|---|
| `risk-commander` | 编排层 | 不持有任何业务工具；不得跳过质疑官 |
| `signal-hub` | 内部只读聚合 | 不判断风险是否成立 |
| `due-diligence` | **唯一外部 PII 触点** | 只摆事实不下结论 |
| `risk-analyst` | 零工具纯推理（求证成立） | 剥夺取证权，防确认偏差 |
| `devils-advocate` | 零工具纯推理（求证不成立） | 对自动执行有一票阻断权 |
| `disposition-executor` | **唯一写触点** | 零自主决策，仅规则驱动 |
| `compliance-auditor` | 唯一 Trace 读 + 知识库写 | 只报告不修复 |

**Agent 数量是数出来的**：6 = 5 个权限等价类 + 1 个目标函数对立拆分。
判据可证伪——合并任意两个都会越权，再往下拆无增益。

## 关键 Skill 与工具链

- **16 个 Skill** 分三层：L3 领域判断层 12 个全自研；L2 领域封装层 4 个（自研外壳 + 编排官方云能力）；
  L1 云操作层直接调官方用云 Skills，不自研。
- **4 个 MCP Server**：`credit-core-mcp` / `bureau-mcp` / `judicial-mcp` / `txn-mcp`。
  Mock 与真实接入**零 Schema 差异**，复赛只换实现不改调用链。
- **推荐组件**：Nacos（Skill 与路由表灰度回滚）、Higress（凭证透传 + PII 出站脱敏）、
  PolarDB PG + pgvector（证据账本与向量库）、RocketMQ（顺序消息保并发一致性）、
  LoongSuite + AgentScope Studio（OTel GenAI 语义可观测）。

## 业务价值与可复制性

**价值**　预警降噪 ≥60%；端到端处置从 0.5–2 个工作日压到分钟级；
**误杀率 ≤2%**（防止错误抽贷）；证据完备率 100%、无证据结论率 0；高风险动作审批覆盖 100%。

**可复制性**　可迁移资产是**拓扑与契约**而非业务规则。更换 MCP 数据源与领域 Skill 后，
同一套 Agent 拓扑、证据账本、执行闸门可直接平移到保险理赔核赔、供应链金融、
反洗钱可疑交易调查、券商适当性管理、医保基金监管。
